# CityBoard Research

## 목표
- 지역/커뮤니티 중심 게시판 서비스의 MVP 범위를 빠르게 구현 가능한 형태로 정리한다.
- 권한, 게시글 공개 범위, 관리자 운영 규칙을 서버 중심으로 일관되게 설계한다.

## 문서 기반 핵심 범위
- 게시판: 자유게시판, 공지사항, 질문게시판, 자료실
- 역할: 비회원, 회원, 관리자
- 인증: 이메일/비밀번호, Google, Kakao, Naver, GitHub
- 게시글 유형: 일반글, 공지글, 비밀글, 익명글
- 상호작용: 댓글/대댓글(1단계), 좋아요, 신고, 북마크
- 운영: 신고 5회 누적 시 자동 숨김, 관리자 검토/복원/삭제, 회원 차단, 익명 작성자 확인
- 기타: 검색, 마이페이지, 파일 업로드, 관리자 대시보드

## 주요 정책 정리
### 권한
- 비회원: 글 작성만 가능, 수정/삭제/댓글/좋아요/신고/북마크 불가
- 회원: 본인 글 수정/삭제, 댓글/좋아요/신고/북마크 가능
- 관리자: 전체 글/댓글 관리, 공지/자료실 관리, 신고 처리, 회원 차단, 익명 작성자 확인 가능

### 게시글 공개 규칙
- 공지글: 관리자만 작성, 상단 고정
- 비밀글: 자유게시판/질문게시판에서만 허용, 작성자와 관리자만 열람
- 익명글: 공개 작성자명은 `익명`, 관리자는 실제 작성자 확인 가능
- 자료실: 관리자 업로드 전용으로 보는 것이 문서상 가장 일관됨

### 신고/숨김
- 신고 주체: 회원
- 신고 대상: 게시글, 댓글
- 게시글은 5회 누적 시 자동 숨김 처리
- 댓글 자동 숨김 여부는 문서상 불명확하여 추후 확정 필요

## 기술 방향
- Next.js App Router 기반 풀스택 구성
- Route Handlers + Prisma + PostgreSQL
- Auth.js(NextAuth)로 이메일/소셜 로그인 통합
- 업로드는 Supabase Storage 또는 AWS S3
- 공개 페이지는 SSR/SEO, 데이터 변경은 Server Actions/Route Handlers 중심

## 설계 시 주의점
- 권한 체크를 UI가 아니라 서버에서 강제해야 함
- 비밀글/숨김글/익명글의 목록/검색 노출 규칙을 중앙화해야 함
- 신고 누적 계산은 중복 신고 방지를 위해 사용자 단위 unique 처리 권장
- 관리자 익명 작성자 조회는 감사 로그를 남기는 편이 안전함

## 확인이 필요한 오픈 질문
- 댓글도 신고 5회 시 자동 숨김할지 여부
- 익명글과 비밀글의 동시 허용 여부
- 차단된 회원의 읽기 권한까지 막을지 여부
- 비회원 글의 소유 추적 방식을 어느 수준까지 둘지 여부

## 권장 MVP 결정
- 공지/자료실 작성은 관리자 전용으로 확정
- 비회원 기능은 "글 작성만"으로 제한
- 자동 숨김 기준은 `중복 없는 신고자 5명`으로 정의
- 검색 결과에서는 비밀글/숨김글을 비권한 사용자에게 노출하지 않음
